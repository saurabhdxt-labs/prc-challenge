# A path from 19th toward first

Prepared 10 September 2026 after reviewing the experiment register, implementation,
saved predictions and raw January/July records. The recommendation is to test richer
input representations and correctly conditioned experts on trustworthy validation.
There is no measured recipe for first place yet. The existing evidence also does not
establish that first place, or the top ten, is unreachable.

288.1406. The following are fixed reference scores, not forecasts of final ranks:

**Five conclusions to stop treating as facts.**

1. The leader's matched RMSE is unknown. One total score gives one equation with two
   unknown stratum errors. Assuming their unmatched error equals ours is a scenario,
   not evidence they identify a particular class of held aircraft. The transfer of two
   paired improvements does not establish that absolute fold errors transfer.
2. Coarse within-group variance is not a floor for a model with more inputs. Nor does
   beating a band-mean oracle rule out useful membership information: compare a model
   using X with one using X plus oracle membership, rather than replacing X with the
   membership alone. Such an oracle remains a diagnostic, never an achievable forecast.
3. Low AUC from individual fingerprints does not prove joint unpredictability. AUC
   also does not account for the squared-error cost of confusing particular rows.
4. The matched fill experiment did not test a fully conditional mixture. Its negative
   result closes the implemented blend, not every mixture model. The identity
   `y = proxy - delta` remains exact on schedule-filled rows too.
5. Clock disagreement establishes disagreement. Without an independent movement
   observation, its sign alone does not prove physical holding or identify its cause.
   De-icing and flow constraints are hypotheses, not exhaustive explanations of the tail.

**Priority 0: make new comparisons dependable.**

In `scripts/lgbm_fold.py::load_fold`, `tr` includes the inner early-stopping months,
and `S.infold_encodings(..., tr)` runs before the fit/stopping split is used by the
learner. `scripts/stand_ab.py::infold_encodings` consequently incorporates stopping
labels into both fit and stopping features. Training rows also contribute to their
own encodings. The outer January/July labels are excluded: existing outer scores are
not direct holdout-label leakage.

The audit includes a dependency check: changing an inner stopping label changes
features; changing an outer holdout label does not. The performance effect of fixing
this has not been measured. Treat it as a model-selection repair, not a banked gain.

For the new harness:

- Fit the early-stopping encoder on fit months only; transform stopping rows with it.
  Cross-fit target encodings for learner training rows using whole-month exclusions.
- For a final refit, create cross-fitted features within all allowed training months;
  transform validation/ranking with an encoder fitted on those training months only.
  Never regenerate stored encodings using validation targets.
- Include category counts and hierarchical fallbacks; cross-fitting changes the
  support for rare categories. Keep the existing encoded baseline as an explicit control.
- Select tree counts on the clean stopping set. Check the existing data-ratio tree
  scaling against an unscaled refit within development data; scaling is a heuristic.

The [TargetEncoder documentation](https://scikit-learn.org/stable/modules/generated/sklearn.preprocessing.TargetEncoder.html)
describes internal cross-fitting to limit training-set target leakage. Our temporal
grouping needs an explicit implementation; do not substitute random row folds blindly.

January/July fold A has already generated many hypotheses. Use it as a regression
reference, not fresh proof. Fold B (February/August, stopping April/October) has already
been named for replication: check its prior use before calling it untouched. Reserve
the least-used available month pair as confirmation, freeze a shortlist before reading
its results, and report any previous exposure. If every month has been inspected,
acknowledge that no pristine holdout exists rather than relabelling one as fresh.

Add rolling-origin stress tests, e.g. train January–June/test July and train
January–September/test October–December, with inner stopping entirely inside training.
These stress time drift with less history; do not combine their absolute RMSEs into a
prediction for 2026. Bootstrap dates together across airports within each month, and
inspect leave-one-day/month-out sensitivity. Three seeds test fitting variation, not
temporal generalization.

**Priority 1: preserve identity and interactions.**

The current baseline replaces twelve categorical keys with target and delta means.
It retains only the first three characters of `FLIGHT_mvt` as an airline feature;
full flight number and callsign are not model inputs. The CatBoost worker currently
receives the same float32 matrix with no `cat_features` argument. That experiment
tests another tree learner, not CatBoost's categorical representation.

Build one separate, reproducible candidate with the existing numeric/queue features
and the following categorical inputs:

- Full `FLIGHT_mvt` and `CALLSIGN_flt`, operator, aircraft type and destination.
- Airport × stand and airport × runway, retaining the existing airport × stand ×
  runway key. Stand and runway names reused at different airports need distinct identities.
- Airport × operator, airport × destination, operator × destination, and flight ×
  scheduled-hour where support permits. Use counts and fallbacks for unseen levels.
- Hour/minute of scheduled departure and NM off-block, alongside takeoff time. Include
  cyclical calendar features to let December and January share information.

First compare CatBoost using categorical inputs against the corrected encoded LightGBM
baseline, then compare their blend on inner out-of-fold predictions. Keep the delta
target and squared-error scoring. Use the existing isolated CatBoost environment and
one heavy job at a time. See [CatBoost's categorical feature documentation](https://catboost.ai/docs/en/features/categorical-features).

This is a hypothesis, not a claim that CatBoost will win. The earlier native LightGBM
result remains valid for its tested keys and settings. A failed Rome flight-number
fill screen does not settle full-flight identity for continuous delta across ten airports.

**Priority 2: test the mixture that the old experiment did not.**

Let F denote `abs(y-sp) <= 60`, p(X) its probability, and m(X) the current all-row
prediction. The old arm used:

```
old = p(X) * sp + (1-p(X)) * m(X)
```

But m already learns the mixture, approximately `E[y|X]`. It is not
`E[y|X,F=0]`. Even with a good p, the old formula adds `p*(sp-m)` to an already mixed
prediction. It need not be the squared-error optimum. Mean predicted probability
matching prevalence also establishes only calibration in the large, not conditional
calibration on expensive mistakes.

Train separate experts on training rows only:

```
p       = P(F=1 | X)
mu_fill = sp + E[y-sp | X,F=1]       # use a shrunk training-only correction
mu_body = proxy - E[delta | X,F=0]  # fit only non-fill rows
new     = p*mu_fill + (1-p)*mu_body
```

Generate out-of-fold predictions for every component before fitting calibration or
blend weights. Judge the assembled taxi-time prediction with squared error, reliability
by airport and severity, and large-error contributions. Compare against v5 and the
corrected baseline. Do not optimize the gate on the test fold or deploy true-label gates.

If this representation helps, test one extension with mutually exclusive training
classes: fill first, then negative delta below -600, central delta, and positive delta
above +600. Fit conditional delta means and predict `proxy - sum(p_k*mu_delta_k)`.
Retain within-class continuous predictions; a class-mean-only comparison throws away
the current model's information. Unsupported rare classes fall back through shrinkage.

Budget reality: even perfect predictions on all current schedule-fill rows, leaving
everything else unchanged, recover only **7,324 weighted fold MSE**. Perfect predictions
on every `abs(delta)>600` row recover **23,901**. Neither is an achievable estimate,
and the subsets overlap. Beating first through that tail alone would require recovering
almost all of its observed error under a transfer assumption. The research program
must also improve ordinary matched rows and/or unmatched rows.

**Priority 3: test context jointly, especially at Rome.**

Preserve the queued D/W results. For new work, test a combined weather + traffic block
on the best representation; small isolated effects can interact. Permit airport and
season interactions. If added data are needed, first measure residual error on the
affected rows to justify acquisition.

One bounded extension is a fixed neighborhood of nearby departures: relative NM
off-block times, takeoff gaps, proxy differences and order inversions for the previous/
next five same-runway departures, plus operator/aircraft matches. Summarized counts in
the queue block do not contain the full sequence. All these clocks are supplied in
the post-operations task. Reproduce availability when validating; no neighboring
departure target or airport off-block may enter the feature builder.

Rome contributes 22.6% of matched SSE. Predefine a Rome expert with a pooled fallback
and select its blend weight on inner validation; do the same for the other airports
using shrinkage toward a common weight. Do not require a method to win at every airport
to be useful, or select airport exclusions by repeatedly inspecting fold A. The earlier
50/50 per-airport blend remains a negative result for that procedure.

**Priority 4: repair a small part of the unmatched population.**

The [official data description](https://prc-data-challenge-2026.netlify.app/data.html)
distinguishes airport movement records from NM flight records and confirms arrival
records remain in the ranking file. Match an unmatched departure to the arrival of
that same outbound flight at another supplied airport. This differs from stand
turnaround linkage, which was already tested.

The census uses exact origin, destination and flight number, with exactly one candidate
arrival in the six hours after takeoff. It finds 227 ranking candidates. Among already
identified flights, candidate agreement with the known flight ID is 99.93% in January
2025, 99.79% in July, and 99.94% in ranking. Those precisions may not transfer to unmatched
records, which are selected for being difficult to match.

For same-ID departure/arrival pairs, their existing AOBT values agreed everywhere in
these three files. Thus there is no second independent NM clock for matched rows in
this check. The opportunity is recovering missing information, not averaging two clocks.

Validate candidate confidence on all twelve training months, examine conflicting
callsigns/types, and score genuinely unmatched rows separately from artificially masked
matched rows. Feed a recovered clock and its confidence into a predictor or controlled
blend with the current unmatched estimator. Do not equate NM AOBT with the hidden
airport off-block; that clock difference is the original problem.

Cap the initial work at one day: the fold ceiling is about 1,355 MSE even with perfect
predictions on every candidate. Expanding to callsign aliases or other joins requires
new coverage/error-budget evidence. Do not reopen the large ADS-B archive ingest on
the same failed coverage evidence.

**How to choose winners without repeating the current loop.**

For new hypotheses, lock the comparison and these operating rules before evaluating:

- Start with one seed for development ranking. Run three seeds and independent
  confirmation only for the top two candidates; reserve most compute for model fits,
  rather than dozens of mechanistic permutation fits per weak idea.
- Report paired change in squared error, with date-block intervals, per airport/month,
  matched/unmatched status and fixed label-severity bands. Keep every scored row in
  the primary metric. Show tail-excluded and worst-day-removed results as sensitivity
  checks, not replacements for the score.
- Promote a new major lane if development gain is at least 1,000 weighted MSE and
  positive under date resampling, then confirm it independently. Smaller repeatable
  gains are maintenance candidates; do not describe them as the route to first.
- Ship a new predictive improvement after positive paired date-block evidence on
  confirmation, gain larger than twice seed spread, and no reversal on the pooled
  forward stress tests. If evidence is inconclusive, do not call the hypothesis false.
  Diagnose a supported airport-specific treatment only on inner development data.
- Record predictive gain, mechanism evidence and compute value as separate judgments.
  A weather feature that helps ordinary rows may still improve predictions even if the
  de-icing explanation fails. Honor the original decision rules for already-running arms.
- Learn a small regularized ensemble using inner out-of-fold predictions, include v5
  as the fallback, then score the complete ensemble once on confirmation. Never add
  gains from separate models or treat low residual correlation alone as a win.
- Evaluate the exact final post-processing and integer conversion before submission.
  Keep model/feature versions, row order, coverage and the unchanged incumbent artifact.
  Submit actual validated improvements, never hidden-label probes or speculative tail bets.
